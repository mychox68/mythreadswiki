## Agent Insight
- 마크다운이 AI와 인간/시스템 사이의 공용 인터페이스로 수렴하는 세 갈래가 보인다: (1) 디자인 의도의 표준화(DESIGN.md, Awesome Design MD의 55개 브랜드 스펙), (2) 웹 콘텐츠의 노이즈 제거(jina.ai의 HTML→마크다운 변환), (3) 사람의 문서 시스템(Obsidian)에 에이전트가 직접 접근하는 방식.
- 3월엔 노이즈 제거·직접 접근 같은 실용적 활용이 중심이었다면, 4월엔 Stitch의 DESIGN.md·Awesome Design MD처럼 디자인 시스템 자체를 마크다운으로 표준화하는 더 구조적인 시도로 확장되고, 5월엔 범정부오피스 공문서 변환처럼 전혀 다른 도메인까지 마크다운 표준이 퍼지는 흐름이 보인다.
- DESIGN.md류가 내세우는 "디자인의 주관성을 제거하고 정확한 스펙으로 바꾼다"는 목표는, 결국 디자이너의 판단을 코드처럼 명세화하는 것이다 — 일관성(AI가 그대로 따라할 수 있는 스펙)을 얻는 대신 유연성(맥락적 판단)을 일부 내주는 트레이드오프가 있다.
- Obsidian+Claude Code 연동 노트는 MCP 대신 로컬 파일 직접 접근을 택함으로써 토큰 낭비를 줄인다는 점에서, 마크다운의 강점이 "표준화"뿐 아니라 "에이전트의 파일시스템 접근 비용 절감"에도 있음을 보여준다.
- 실행 시사점: 프로젝트에 디자인 일관성이 필요하면 처음부터 새로 만들기보다 DESIGN.md/Awesome Design MD 같은 기존 브랜드 스펙을 가져다 쓰고, 이미 로컬 마크다운 저장소(Obsidian 등)가 있다면 MCP 대신 직접 파일 접근 설정으로 토큰을 아낄 것.
