# Orca 가이드

> [!question] 질문
> omp/OpenCode/Zed/Cursor에 이어서 "orca"도 조사해달라.

## TL;DR

Orca는 **Stably AI**(Y Combinator 배치)가 만든 무료 오픈소스(**MIT 라이선스** — 최초 조사 때는 Apache 2.0으로 잘못 파악했으나 공식 GitHub README에서 MIT로 확인됨) **ADE(Agent Development Environment)**입니다. Claude Code, Codex, Cursor CLI, GitHub Copilot, OpenCode, Grok 등 **30개 이상의 기존 에이전트 CLI를 자기 구독 그대로 가져와서**, git worktree 여러 개에 서로 다른 에이전트를 동시에 돌리고 결과를 비교하는 데스크톱 앱입니다. GitHub 스타 15,746개 이상(2026-07-19 기준 검색 결과).

지금까지 조사한 omp/OpenCode/Claude Code(에이전트 코어), Zed/Cursor(자체 AI 내장 에디터)와는 또 다른 층위입니다 — **Orca 자신은 모델이나 에이전트를 갖고 있지 않고, 남의 에이전트 CLI 여러 개를 동시에 굴리는 "관제탑" 역할만** 합니다.

이 환경에는 **Orca v1.4.145**가 설치되어 있습니다(2026-07-19 재확인, 최초 조사 시점인 2026-07-12에는 v1.4.137이었음 — `C:\Users\HOME\AppData\Local\Programs\orca\Orca.exe`, Electron 기반 데스크톱 앱). 홈페이지에 "new features shipped daily"라고 적혀 있을 만큼 업데이트가 잦으니, 버전·기능 세부사항은 주기적으로 재확인이 필요합니다.

이 환경에서 실제로 써본 **오케스트레이션(task/dispatch/메시징) 서브시스템**에 대한 상세 가이드는 [[20260719-131244-orca-오케스트레이션-기능]] 참고.

## 2. 핵심 개념

### 여러 에이전트를 worktree에 나눠 돌리기
같은 저장소에서 git worktree를 여러 개 만들고, 각 worktree에 다른 에이전트(Claude Code, Codex, OpenCode, Grok 등)를 동시에 붙여 같은 작업을 시켜본 뒤 결과를 비교하는 게 전형적인 사용 패턴입니다.

### 에이전트를 직접 만들지 않고 "모아서 굴린다"
Orca는 자체 LLM이나 자체 에이전트 로직이 없습니다. 대신 이미 구독 중인 Claude Code, Codex, OpenCode 등 CLI를 그대로 불러와 실행합니다 — omp/OpenCode가 "직접 만든 에이전트 코어"인 것과 대비됩니다.

### VS Code 에디터 내장 + 터미널 + 브라우저 제어
앱 하나에 VS Code 기반 에디터, 터미널, 브라우저가 같이 들어있어서 에이전트가 브라우저까지 직접 조작하는 걸 지켜볼 수 있습니다. 파일/이미지를 드래그해서 에이전트 프롬프트에 바로 넣을 수 있고, 자동 저장이 전역으로 적용됩니다.

### 원격 박스 실행
로컬이 아니라 원격 머신에서 파일 편집·git·터미널을 그대로 쓸 수 있고, 자동 재연결과 포트 포워딩을 지원합니다.

### 오케스트레이션(orchestration) — 별도 조정 레이어
단순 병렬 실행을 넘어, 여러 에이전트 터미널을 하나의 코디네이터가 관리하는 구조화된 레이어가 따로 있습니다. Task 생성 → 특정 터미널에 dispatch → `worker_done`/`escalation` 대기 → 필요 시 decision gate로 사람 판단 개입, 이라는 흐름입니다. 공식 소개 문구로는 "The AI Orchestrator for 100x builders", "Fan one prompt across five agents, each in its own isolated git worktree — compare the results and merge the winner." 상세 명령어와 사용 규칙은 [[20260719-131244-orca-오케스트레이션-기능]]에 정리.

### GitHub/Linear 연동, 모바일 모니터링, Design Mode
- GitHub·Linear 이슈에서 바로 worktree를 열 수 있어 컨텍스트 전환 없이 작업 시작 가능.
- iOS/Android 모바일 앱으로 에이전트 상태를 모니터링하고, 완료 알림을 받거나 후속 지시를 보낼 수 있음.
- Design Mode: 내장 브라우저로 에이전트가 만든 UI를 바로 프리뷰.

## 3. 지금까지 조사한 도구들 사이에서의 위치

| 계층 | 도구 | 자체 에이전트/모델 보유 |
|---|---|---|
| 에이전트 코어(터미널) | omp, OpenCode, Claude Code | O — 자체 런타임과 도구 시스템 |
| AI 네이티브 에디터 | Zed, Cursor | O(Zed는 ACP로 외부도 가능) — 자체 편집/예측 모델 |
| **에이전트 오케스트레이션 IDE** | **Orca** | **X — 위 에이전트들을 그대로 가져와 병렬로 관제** |

Zed의 ACP가 "에디터 하나에 에이전트를 갈아 끼우는" 방식이라면, Orca는 "여러 에이전트를 동시에 여러 worktree에 뿌리고 비교"하는 좀 더 관리자/플릿(fleet) 관점에 가깝습니다. Cursor 3가 최근 "병렬 에이전트 관리" UI로 방향을 튼 것과 개념적으로 겹치지만, Cursor는 자체 에이전트를 밀고 Orca는 남의 에이전트를 그대로 쓴다는 점이 다릅니다.

## 4. 이 환경에서 확인된 로컬 상태

- `Orca.exe` v1.4.145 확인(2026-07-19 재확인). 최초 설치 시점(2026-07-12)엔 v1.4.137이었음 — `C:\Users\HOME\AppData\Local\Programs\orca\`
- Electron 번들 파일들(chrome_*.pak, v8_context_snapshot.bin, ffmpeg.dll 등)로 데스크톱 앱 형태 확인
- 2026-07-19 기준: `orchestration` 스킬(`C:\Users\HOME\.claude\skills\orchestration`)을 통해 orchestration 서브커맨드(`task-create`, `dispatch`, `check --wait`, `gate-create` 등)를 실제 사용 중 — Settings > Experimental에서 활성화 필요한 실험적 기능
- PATH에는 안 잡혀 있어 `orca` 커맨드로 터미널에서 바로 실행은 안 되고, Windows Programs 폴더의 실행 파일로 직접 열어야 함 (단, orchestration 스킬은 `orca` CLI가 PATH에 있다는 것을 전제로 함 — 실제 세션에서 CLI 경로가 잡혀 있는지는 별도 확인 필요)
