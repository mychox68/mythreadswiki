# 컴퓨터 유주나 브라우저 유주를 못 쓰는 것도 이상한 거 아니야 그리고 이런 거는 정상적으로 잘 될 거 아니야 윈도우라서 안 되나 왜 이거부터 뺐지 노티파이 때문에 그런가

> [!question] 질문
> 컴퓨터 유주나 브라우저 유주를 못 쓰는 것도 이상한 거 아니야 그리고 이런 거는 정상적으로 잘 될 거 아니야 윈도우라서 안 되나 왜 이거부터 뺐지 노티파이 때문에 그런가

## 답변

**1. 결론**

Computer Use와 Browser Use를 못 쓰는 상태를 정상이라고 보면 안 된다. Windows라서 원래 안 되는 기능도 아니다. OpenAI 공식 문서상 Computer Use는 Windows와 macOS에서 지원되며, 내장 Browser도 Windows 데스크톱 앱의 정식 기능이다.

- [Computer Use 공식 문서](https://learn.chatgpt.com/docs/computer-use)
- [Browser 공식 문서](https://learn.chatgpt.com/docs/browser)

**2. 현재 실제 상태**

현재 설정과 앱 로그는 다음과 같다.

| 기능 | 현재 상태 |
|---|---|
| Browser 플러그인 | `enabled = true` |
| 앱의 Browser 판정 | `available=true`, `browserPane=true` |
| Chrome 플러그인 | `enabled = true` |
| Computer Use 플러그인 | `enabled = false` |
| Computer Use 차단 정책 | 없음 |
| `notify`와 네이티브 파이프 | 계속 활성 |
| app-server | 확인 시점에는 재기동되어 실행 중 |

따라서 Browser는 설정상 빠져 있지 않다. 실제 화면에서 못 쓴다면 Browser 설정 자체보다 `app-server`가 죽으면서 도구 연결이 끊기는 증상일 가능성이 높다.

**3. Computer Use를 먼저 뺀 이유**

당시에는 다음 요소들이 한 덩어리로 의심됐다.

- `@oai/sky` 기반 Windows UI 제어 직후 종료가 관측됨
- `computer-use` 플러그인 활성
- `codex-computer-use.exe turn-ended` notify 존재
- `openai-bundled` marketplace 중복
- `app-server`가 `0xC000013A`로 종료

그래서 되돌릴 수 있는 진단 조치로 Computer Use 플러그인을 비활성화하고 marketplace 중복을 정리했다. 이후 재시작 5회, 생존 검사 20회와 30회를 통과해서 당시에는 완화 효과가 있는 것처럼 보였다. (참고: [노트 1])

**4. 지금 확인된 검사의 한계**

Computer Use 플러그인을 끄자 사용자가 Computer Use를 쓸 수 없게 됐지만, 앱 본체의 notify와 native pipe는 그대로 실행됐다. 즉 notify를 의심하면서 실제로는 Computer Use의 사용자 기능만 제거한 셈이다.

앱 본체가 notify를 별도로 자동 복원하기 때문에 플러그인을 꺼도 `codex-computer-use.exe turn-ended`는 계속 남는다. (참고: [노트 2])

Computer Use 플러그인이 꺼진 현재도 app-server가 다시 여러 번 종료됐다. 따라서 Computer Use 플러그인이 단독 원인이라는 가설은 약해졌고, 플러그인을 계속 꺼둔 채 기능을 포기할 근거도 약해졌다. notify 또는 앱 본체의 네이티브 파이프는 아직 제대로 A/B 검사하지 못했다.

**5. notify 때문인가**

현재 판정은 가능성이 남아 있지만 아직 증명되지 않았다는 것이다.

`notify`는 원래 Codex가 턴 종료 때 JSON payload와 함께 호출하는 정상적인 알림 명령이다. 앱이 이를 자동 복원하는 것도 의도된 동작으로 보인다. 다만 이 머신에서는 그 명령이 Computer Use 네이티브 실행 파일이고 app-server 종료 코드가 외부 중단 계열인 `0xC000013A`이므로 조사 대상에서 완전히 제외할 수는 없다.

- [OpenAI 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)

**6. 다음 통제 방향**

Browser는 이미 켜져 있으므로 건드릴 이유가 없다. Computer Use는 플러그인만 단독으로 재활성화하고 notify와 marketplace 등 다른 값은 그대로 둔 통제 실험이 적절하다.

재활성화 전후에 동일한 생존 검사를 돌리면 다음을 분리할 수 있다.

1. Computer Use 자체가 Windows에서 정상 작동하는가
2. 플러그인 재활성화가 종료 빈도를 높이는가
3. 플러그인과 무관하게 notify 또는 native pipe가 종료에 관여하는가

아직 재활성화나 앱 재시작은 수행하지 않았다. 당시 작업 흐름과 설정 제거 순서는 작업로그에도 남아 있다. (참고: [노트 3])
