# Orca 오케스트레이션 기능

> [!question] 질문
> Orca 사용 중, 오케스트레이션 기능이 뭔지 알려달라.

## TL;DR

Orca 오케스트레이션은 여러 에이전트 터미널을 하나의 코디네이터가 관리할 수 있게 해주는 **구조화된 조정 레이어**다. `orca-cli`(터미널·워크트리 제어)와 달리, 작업 소유권과 완료 추적 상태(`taskId`/`dispatchId`)를 런타임에 명시적으로 기록한다. [[20260712-233546-orca-가이드]]가 Orca 자체(ADE, 병렬 worktree 운영)를 다룬다면, 이 노트는 그 위에 얹힌 orchestration 서브시스템만 다룬다.

## 핵심 개념

- **Task** — 작업 단위. 의존성 있는 DAG 구성 가능.
- **Dispatch** — 특정 터미널(에이전트)에 작업을 할당.
- **Gate** — 코디네이터/사용자 결정이 있을 때까지 진행을 막는 지점.
- **Message** — 터미널 간 상태·질문·완료 메시지. 타입: `status`, `dispatch`, `worker_done`, `escalation`, `decision_gate`, `heartbeat` 등.

## 사전 조건

- `orca status --json`로 런타임이 떠 있는지 확인.
- Settings > Experimental에서 orchestration 기능 활성화 필요.
- `orca` CLI가 PATH에 있어야 함.

## 기본 흐름 (코디네이터 입장)

```bash
# 1. 워커 터미널 준비
orca terminal create --worktree active --title <작업명> --command "codex" --json
orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 60000 --json

# 2. 작업 생성 및 할당
orca orchestration task-create --spec "<작업 내용>" --json
orca orchestration dispatch --task <task_id> --to <handle> --inject --json

# 3. 완료/에스컬레이션 대기
orca orchestration check --wait --types worker_done,escalation,decision_gate --timeout-ms 900000 --json
```

큰 작업 전체를 자동으로 돌리는 `orca orchestration run --spec "<큰 작업>" --json`도 있다 (즉시 run ID 반환, `task-list`로 진행 상황 조회).

## 메시징 / 질의응답

```bash
orca orchestration send --to <handle> --subject <제목> --body <내용> --type <타입> --json
orca orchestration ask --to <handle> --question <질문> --options <csv> --json   # 블로킹 질문
orca orchestration reply --id <msg_id> --body <답변> --json
orca orchestration inbox --json
```

## 게이트(결정 지점)

```bash
orca orchestration gate-create --task <task_id> --question <text> --json
orca orchestration gate-resolve --id <gate_id> --resolution <text> --json
```

DAG 진행 중 사람/코디네이터 판단이 필요한 시점에 쓴다. 워커가 던진 `ask`에는 `gate-create`가 아니라 `reply`로 답한다.

## 중요한 구분 — Orchestration vs 단순 Handoff

- "다른 에이전트에게 넘겨줘/handoff" 같은 표현은 **완전한 소유권 이전**으로 취급되고, 이 경우 오케스트레이션 라이프사이클(`task-create`, `dispatch --inject`, `check --wait`)을 쓰지 않는다. 대신 `orca worktree create --prompt ...` 또는 `orca terminal send ...`로 끝낸다.
- "감독해줘/모니터링해줘/완료를 기다려줘/DAG로 조율해줘" 처럼 **명시적으로 감독을 요청**할 때만 오케스트레이션(`task-create`/`dispatch`/`check --wait`)을 사용한다.
