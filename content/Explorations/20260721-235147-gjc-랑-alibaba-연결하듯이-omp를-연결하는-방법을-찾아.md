# gjc 랑 alibaba 연결하듯이 omp를 연결하는 방법을 찾아

> [!question] 질문
> gjc 랑 alibaba 연결하듯이 omp를 연결하는 방법을 찾아

## 답변

**결론부터: omp를 Alibaba Token Plan에 붙이는 방법은 gjc와 사실상 동일합니다.** gjc는 omp의 하드포크라(참고: [노트 6]) 설정 파일 스키마가 거의 그대로 이어집니다. 볼트 노트만으로는 omp 쪽의 정확한 명령/파일 형식이 안 나와 있어서, 로컬에 설치된 `omp v16.4.8`(`~/.bun/bin/omp`)의 실제 소스코드(`@oh-my-pi/pi-coding-agent`)를 직접 열어 확인했습니다.

### 1. gjc ↔ Alibaba가 어떻게 연결됐었는지 (참고: [노트 1])

gjc는 `gjc setup provider --compat anthropic --provider alibaba-token-plan --base-url ... --api-key-env ALIBABA_TOKEN_PLAN_API_KEY --model qwen3.7-plus` 명령으로 `~/.gjc/agent/models.yml`에 provider를 등록했습니다. hermes도 같은 Anthropic 호환 엔드포인트를 `hermes config set`으로 붙였습니다(참고: [노트 2]).

### 2. omp에는 `gjc setup provider` 같은 서브커맨드가 없다 (직접 검증)

`omp setup --help`를 보면 `setup`은 `python|speech` 의존성 설치 전용이고, `omp config set`은 화이트리스트된 고정 키만 받습니다(`providers.alibaba-token-plan.baseUrl`을 넣어보니 `Unknown setting` 에러). 대신 gjc가 쓰는 것과 **같은 계열의 파일**을 omp도 그대로 갖고 있습니다.

### 3. 실제 메커니즘: `~/.omp/agent/models.yml`

`src/config/models-config-schema.ts`(omp 소스)를 읽어 확인한 provider 스키마:

```yaml
providers:
  alibaba-token-plan:
    baseUrl: https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic
    apiKey: ALIBABA_TOKEN_PLAN_API_KEY   # 문자열 그대로 env var 이름으로 먼저 조회됨
    api: anthropic-messages              # gjc의 --compat anthropic 과 동일
    models:
      - id: qwen3.7-plus
      - id: qwen3.7-max
      - id: qwen3.8-max-preview
```

- `apiKey` 필드는 `resolveConfigValue()`가 처리 — 값이 `!`로 시작하면 셸 커맨드 실행, 아니면 **먼저 동일 이름의 환경변수를 찾고**(`Bun.env[valueConfig]`), 없으면 리터럴 문자열로 씀. 즉 gjc의 `apiKeyEnv` 필드와 동일한 역할을 `apiKey`에 env var 이름을 넣는 것으로 수행합니다.
- gjc용으로 이미 `$env:ALIBABA_TOKEN_PLAN_API_KEY`를 PowerShell 프로필에 export해뒀으므로(참고: [노트 1]) 키를 새로 발급/등록할 필요 없이 그대로 재사용했습니다.
- `api: anthropic-messages`는 omp 소스의 `ApiSchema`에 실제로 존재하는 유효한 enum 값으로 확인됨(gjc 값과 동일).
- `cc-switch`는 gjc·omp 둘 다 지원하지 않으므로(참고: [노트 4]) GUI 경유는 불가하고, 이 방식(직접 파일 편집)이 유일한 경로입니다.

### 4. 실제 적용 및 검증 결과 (2026-07-21)

- `C:\Users\HOME\.omp\agent\models.yml` 신규 생성 완료 (위 YAML 그대로 적용).
- `omp models find qwen` → `alibaba-token-plan` provider 아래 3개 모델(qwen3.7-max/plus, qwen3.8-max-preview) 정상 노출 확인.
- 실제 API 호출 검증: `omp -p "reply with exactly the word OK" --model alibaba-token-plan/qwen3.7-plus` → 응답 `OK` 정상 수신. **연동 완전히 동작함.**
- 참고: 자동화 도구(비대화형 PowerShell 세션)에서는 사용자 프로필 스크립트가 로드되지 않아 처음엔 `401 InvalidApiKey`가 났음 — 프로필이 로드되는 일반 대화형 터미널에서는 문제없이 동작(gjc 때와 동일한 패턴, 참고: [노트 1]).
