# Gajae-Code — OMC가 무거워서 나온 대안, 갈아타야 하나

> [!question] 질문
> 카톡방에서 "OMC도 현재 모델엔 무거워 제작자가 가재코드를 만들었다"는 말이 나왔다. 사용자도 OMC를 쓰고 있는데, 가재코드로 바꿔야 하나?

## 결론 (TL;DR)

**지금 당장 통째로 갈아탈 필요는 없다. 1:1 대체재가 아니라 다른 성격의 도구다.**

- **Gajae-Code(`gjc`)** = OMC와 같은 제작자(Yeachan-Heo)가 만든 **독립 CLI 하네스**. Claude Code/Codex/OpenCode **안에 얹는 플러그인이 아니라, 그 밖에서 별도로 띄우는 도구**.
- README가 대놓고 "No sprawling default skill zoo"(스킬 동물원 안 만든다)라고 선언 — 기본 스킬 **4개**(`deep-interview`, `ralplan`, `ultragoal`, `team`)와 역할 에이전트 **4개**(executor/architect/planner/critic)뿐. OMC(32+ 에이전트, 39+ 스킬)의 방대함을 의도적으로 뺐다.
- **아직 베타**: README 원문 "experimental, beta-stage project. Expect rough edges." 생성 2026-05-26(약 6주), 1,572★/215 fork, MIT, TypeScript+Bun.
- OMC가 이미 제공하는 `wiki`, `project_memory`, `ai-slop-cleaner` 등 이 프로젝트 메모리 시스템이 의존하는 기능은 Gajae-Code에 **없다** — 의도적으로 빼놓은 것.
- 컨텍스트 무거움이 실제로 불편하면, 통째로 바꾸기보다 **둘 다 두고 단순 계획/실행 작업에만 `gjc`를 사이드로 써보는** 정도가 안전하다.

## OMC와 비교

| | oh-my-claudecode (OMC) | Gajae-Code (`gjc`) |
|---|---|---|
| 형태 | Claude Code **플러그인** (내부에 얹힘) | Claude Code 등 **밖에서** 도는 독립 CLI |
| 규모 | 32+ 에이전트, 39+ 스킬 | 4 스킬 + 4 에이전트로 의도적 최소화 |
| 성숙도 | 37.4k★, 오래 검증됨, 사용자가 이미 실사용 중 | 6주, 1.5k★, 베타 명시 |
| 메모리/지식 시스템 | `project_memory`, `wiki`, `notepad` 등 내장 | 없음 (스코프 밖) |
| 컨텍스트 부담 | 스킬/에이전트가 많아 상대적으로 무거움 | 의도적으로 가볍게 설계 |
| 적합한 상황 | 지금처럼 메모리·위키·다양한 스킬을 계속 쓰는 프로젝트 | 단순 "인터뷰→계획→실행" 루프만 필요한 가벼운 작업 |

## 정리

가재코드는 OMC를 대체하려는 게 아니라, **OMC의 핵심 워크플로우 스킬 이름(`deep-interview`, `ralplan`, `ultragoal`, `team` — OMC에도 동일한 이름의 스킬이 있음)만 뽑아서 독립 실행형으로 가볍게 재구성한 사이드 프로젝트**로 보인다. "OMC가 무겁다"는 카톡방 얘기는 정확하지만, 그 해법이 "OMC를 버리고 gjc로 전환"이 아니라 "가벼운 작업엔 gjc, 무거운 프로젝트 관리엔 OMC" 식의 **용도 분리**일 가능성이 높다.
