# Herdr — 에이전트 멀티플렉서

> [!question] 질문
> herdr 이 뭐야?

## TL;DR

**Herdr**는 tmux가 여러 터미널 세션을 관리하듯, 여러 AI 코딩 에이전트(Claude Code, Codex 등)를 하나의 터미널 안에서 워크스페이스/탭/페인으로 관리하는 **에이전트 멀티플렉서**다. Rust로 만든 단일 바이너리이며 Electron 같은 별도 GUI 프레임워크 없이 기존 터미널(WezTerm, iTerm2, Kitty 등) 안에서 동작한다.

## 핵심 기능

- **에이전트 상태 인식**: 사이드바에서 각 에이전트가 작업 중(working)/유휴(idle)/입력 대기(blocked) 상태인지 한눈에 파악
- **터미널 네이티브**: 기존 터미널을 대체하지 않고 그 안에서 실행
- **세션 영속성**: detach해도 에이전트는 계속 실행되며, 재시작 후에도 세션이 유지됨
- **원격 접근**: 서버/VM/맥미니 등 어디서 실행되든 SSH로 어디서든 attach 가능(휴대폰 포함)
- **소켓 API**: 에이전트끼리 pane을 생성하고 서로의 출력을 읽거나 대기하는 것도 지원

## Orca와의 비교 — 설치가 필요한가?

이 환경엔 이미 [[20260712-233546-orca-가이드|Orca]]가 설치되어 있어 목적이 일부 겹친다.

| 구분 | Orca | Herdr |
|---|---|---|
| 형태 | Electron 데스크톱 앱 (VS Code 에디터 + 터미널 + 브라우저 내장) | Rust 단일 바이너리, GUI 없음 |
| 자체 에이전트/모델 | 없음 — 기존 에이전트 CLI를 워크트리별로 관제 | 없음 — 기존 에이전트 CLI를 pane별로 관제 |
| 강점 | 로컬 데스크톱에서 여러 worktree를 나란히 놓고 GUI로 비교 | SSH로 원격 서버/VM에 붙어 가볍게 여러 에이전트 세션 관리, tmux 대체 |
| 무게 | 무겁다(Chromium 번들) | 가볍다(순수 CLI) |

결론: "로컬에서 GUI로 워크트리 비교"가 주 용도면 Orca로 충분하고, "원격/서버에서 터미널만으로 여러 에이전트 세션 관리"가 필요하면 Herdr가 더 맞는다. 둘은 대체재라기보다 로컬 vs 원격 용도로 상호보완적이라 병행 설치도 무리 없음.

## Windows 설치 기록 (2026-07-18)

공식 설치 스크립트(PowerShell)로 설치 완료.

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
```

- 설치 버전: `0.7.4-preview.2026-07-17-813fec141faa` (x86_64-pc-windows-msvc)
- 바이너리 위치: `C:\Users\HOME\.herdr\packages\standalone\releases\...\herdr.exe`
- PATH 등록 위치: `C:\Users\HOME\AppData\Local\Programs\Herdr\bin` (User PATH)
- 관리자 권한 불필요, 유저 스코프 설치
- 주의: 설치 스크립트가 PATH를 갱신해도 **이미 열려 있던 터미널 세션에는 반영 안 됨** — 새 PowerShell/Wave 창을 열어야 `herdr` 명령 인식됨
- 다른 설치 옵션: macOS/Linux는 `curl -fsSL https://herdr.dev/install.sh | sh`, Homebrew `brew install herdr`, mise `mise use -g herdr`, 또는 [GitHub Releases](https://github.com/ogulcancelik/herdr/releases)에서 직접 다운로드
