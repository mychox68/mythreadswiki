# 그럼 니가 이렇게 아직 멍청하다는? Obsidian에 이슈 찾아봐, 이미 이슈했는데, 같은 현상인지

> [!question] 질문
> 그럼 니가 이렇게 아직  멍청하다는??  obsidian에 이슈 찾아봐, 이미 이슈했는데, 같은 현상인지.

## 답변

맞다. 기존 이슈 기록을 먼저 확인하지 않고 신규 신고를 권한 것은 잘못이었다.

### 1. 결론: 같은 상위 결함

이 문제는 이미 2026-07-30에 `openai/codex #36012`로 제출했다.

> `[Windows][CLI 0.146.0] MultiAgentV2 custom-agent spawn ends the parent after child task_started with zero model events`

기존 이슈와 오늘 현상은 다음 핵심 불변식이 같다.

- subagent 실행 중 문제가 생긴다.
- 자식 오류가 격리되지 않는다.
- 부모 Codex까지 최종 답변 없이 종료된다.
- PowerShell 프롬프트로 조용히 복귀한다.
- `panic`, OOM, Windows 크래시 이벤트가 없다.

(참고: [노트 1])

### 2. 오늘은 재현 단계가 조금 달라짐

| 구분 | 기존 #36012 | 2026-08-07 장애 |
|---|---|---|
| Codex | `0.146.0` | `0.147.0` |
| 자식 수 | 1개에서도 재현 | 2개 병렬 |
| 자식 진행 | `task_started` 직후 0토큰 종료 | 모델 응답 후 `exec`까지 진입 |
| 마지막 경계 | 자식 MCP 초기화 → 부모 `wait_agent` | 부모·자식 동시 code-mode 실행 |
| 오류 | 명시적 오류 없음 | `code-mode host closed its stdout` |
| 결과 | 부모까지 조용히 종료 | 부모와 두 자식이 같은 시각 종료 |

완전히 동일한 세부 재현은 아니지만, `#36012`에서 신고한 “subagent 실패가 부모 CLI 종료로 전파되는 결함”이 `0.147.0`에서도 계속된 것으로 판정한다. 이번에는 병렬 code-mode 도구 실행이 새로운 직접 트리거로 보인다. (참고: [노트 1])

### 3. 중복 `Started`는 이중 spawn이 아님

오늘 부모 기록의 `spawn_agent` 호출은 정확히 두 번이다.

- `/root/inspect_workspace` 한 번
- `/root/video_metadata` 한 번

각 agent를 두 번 생성한 것은 아니다. 이전 조사에서도 화면에 `Started`가 두 번 보였지만 실제 spawn은 한 번이었고, 시작 이벤트와 도구 완료 또는 세션 상속 이벤트가 중복 렌더링된 것으로 판정했다. (참고: [노트 2])

### 4. 운영 및 이슈 처리 판단

`agents.enabled = false`는 당장 작업을 살리는 임시 회피책일 뿐 해결책이 아니다. 기존 진단 노트에서도 서브에이전트를 한 명만 쓰거나 병렬 기능을 포기하라는 권고를 취소했다. 사용자는 정상적인 병렬 작업을 요청할 수 있어야 하며, Codex가 자식 실패를 구조화된 오류로 부모에게 반환해야 한다. (참고: [노트 1])

새 이슈를 만들기보다는 기존 `#36012`에 다음 증거를 추가하는 것이 적절하다.

```text
Still reproducible on codex-cli 0.147.0.

Unlike the original child-startup reproduction, both children progressed
into code-mode exec. The parent and both children then received
"code-mode host closed its stdout" at the same timestamp, and the parent
CLI returned to PowerShell without a final response.

This appears to be the same missing parent/child failure-isolation invariant,
now triggered by concurrent code-mode tool execution.
```

오늘 작업로그에도 동일 DownloadYoutube 요청의 짧은 종료 세션들과 후속 진단 대화가 남아 있다. (참고: [노트 3])
