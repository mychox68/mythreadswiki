# 코덱스 앱이 약 5분 뒤 다시 죽은 현상 확인

> [!question] 질문
> 코덱스 앱이 한참 만에 또 죽네? 한 오분 정도는 됐을 것 같아요 니가 한번 확인을 해 봐

## 답변

### 1. 결론

이번에도 코덱스 앱의 UI 전체가 죽은 것이 아니라 내부 `app-server`만 반복 종료된 동일 계열 장애다. 과거 기록의 빠른 상태 검사를 다시 실행한 결과 `RED: Codex UI is alive but its app-server child is missing`으로 판정됐다. (참고: [노트 1])

### 2. 이번 장애 타임라인

- 앱 시작: 2026-08-08 09:55경 KST
- app-server 종료: 10:01:44
- 자동 재연결 후 재종료: 10:02:29
- 다시 재연결 후 재종료: 10:06:40
- 종료 코드: `3221225786 = 0xC000013A`

`0xC000013A`는 일반적인 네이티브 충돌보다 Ctrl+C·콘솔 종료 같은 외부 중단 계열 코드다. 사용자가 직접 Ctrl+C를 눌렀다는 의미는 아니며, 앱 내부 수명주기에서 같은 종료 상태가 전달됐을 가능성이 크다.

### 3. 배제된 원인

- Windows에 이번 시각의 새 `ChatGPT.exe` 또는 `codex.exe` 크래시 이벤트가 없다.
- Crashpad 덤프가 없다.
- UI 프로세스 8개는 모두 응답 중이었다.
- OOM 또는 자원 고갈 증거가 없다.

따라서 앱 전체·GPU·메모리 크래시보다는 내부 `codex.exe`만 사라져 UI 껍데기가 남은 상태다.

### 4. 이전 조치와의 관계

어젯밤 적용한 설정은 그대로 유지되고 있었다.

- `computer-use@openai-bundled`: 비활성화 유지
- `openai-bundled`: 프로필 경로 하나로 유지
- 중복 marketplace 복귀 없음
- `notify = codex-computer-use.exe turn-ended`: 자동 복원된 채로 존재

따라서 이전 조치는 재현 빈도를 낮췄지만 근본 해결은 아니었다. 이번에는 subagent를 실행하지 않았으므로 `openai/codex #36012`의 구체적인 MultiAgentV2 트리거와는 다르다. 다만 내부 자식 프로세스가 죽고 부모 UI가 복구하지 못한다는 상위 결함은 같다. (참고: [노트 1], [노트 2], [노트 3])

### 5. 다음 조사

자동 복원된 `notify`의 `codex-computer-use.exe turn-ended`가 간헐적으로 종료 신호에 관여하는지는 아직 배제되지 않았다. 다음 단계는 `notify` 값을 다시 쓰는 주체를 먼저 식별하고, 그 뒤 한 변수만 바꾸는 통제 A/B 생존 검사다.

### 6. 후속 조사 — `notify` 자동 복원 주체 확정

자동 복원 주체는 프로필 동기화 스크립트나 Computer Use 런타임의 `setup.ps1`이 아니라 **Windows Codex 데스크톱 앱 본체의 메인 프로세스**다.

- 설치 앱의 `resources/app.asar`에는 사용자 Codex 홈의 `config.toml`을 열어 `notify`를 검사하고, 필요하면 `writeFile`로 다시 쓰는 코드가 들어 있다.
- 앱이 강제하는 값은 `codex-computer-use.exe turn-ended`다. 기존 notify가 있으면 삭제하지 않고 `--previous-notify` 뒤에 직렬화해 래핑한다.
- 이 함수의 결과 상태는 `installed`, `repaired`, `already-present`로 기록된다.
- 실제 데스크톱 로그에서 2026-07-27, 2026-07-31, 2026-08-07에 `repaired`, 2026-08-08 01:29:59 KST에 `installed`, 현재 앱 시작 때 `already-present`가 확인됐다. 즉 01:23경 제거했던 notify를 앱이 약 7분 뒤 직접 다시 설치한 기록이다.
- 호출 조건은 앱이 전달한 데스크톱 기능 상태에서 `computerUse`와 `computerUseNodeRepl`이 모두 활성일 때다. 그 뒤 notify를 보장하고 Computer Use 네이티브 파이프를 시작한다.

따라서 `[plugins."computer-use@openai-bundled"].enabled = false`를 유지해도 notify가 복원될 수 있다. 플러그인 활성화와 데스크톱 앱의 Computer Use 기능 게이트는 별도 제어 계층이다. 현재 로그에도 플러그인은 비활성인데 `computer-use notify config ensure finished status=already-present`와 `computer-use native pipe startup ready`가 이어서 남아 있다.

공식 설정 문서도 이 분리를 뒷받침한다. 사용자 `config.toml`의 `notify`는 알림 시 JSON payload를 받는 명령이며, Computer Use와 관련 설치·활성화 흐름 전체를 막는 공식 정책 키는 일반 플러그인 토글이 아니라 `requirements.toml`의 `features.computer_use = false`다. 브라우저 계층까지 분리하려면 `features.browser_use = false`가 별도로 존재한다. ([OpenAI Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference))

### 7. 현재 판정

- **확정:** notify 자동 복원자는 Windows Codex 앱 본체다.
- **확정:** 복원 트리거는 번들 플러그인 상태가 아니라 데스크톱 Computer Use 기능 가용성이다.
- **미확정:** `codex-computer-use.exe turn-ended` 자체가 `app-server`의 `0xC000013A` 종료를 직접 발생시키는지는 아직 인과관계가 입증되지 않았다.
- **다음 통제 실험 후보:** 앱을 끈 상태에서 정책 차단점을 적용한 뒤 notify 비복원 여부와 app-server 생존 시간을 비교한다. 이번 조사에서는 설정 변경이나 앱 재시작을 하지 않았다.
